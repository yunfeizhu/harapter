# Governance

Harapter begins with a maintainer-led, open-development model.

## Decision making

- Routine fixes and documentation changes use pull request review.
- Public API, compatibility, provider lifecycle, security, and governance
  changes require a written design proposal or decision record.
- Maintainers seek technical consensus and document unresolved trade-offs.
- Capability claims require executable evidence; popularity or brand name is not
  sufficient.

## Maintainers

Maintainers triage issues, review changes, manage releases, and enforce the code
of conduct and security policy. New maintainers should demonstrate sustained,
high-quality contributions across code, review, documentation, and community
support.
